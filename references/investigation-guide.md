# Evidence, explanations and learning

## Keep different claims separate

| Kind | Useful wording | What it does not establish |
|---|---|---|
| Observation | “The supplied table records …” | Measurement validity, representativeness or cause |
| User report | “You report …” | Independent confirmation |
| Preference/constraint | “You want … / must preserve …” | A factual causal explanation |
| Assumption | “For this answer I assume …” | A verified premise |
| Hypothesis | “One possible explanation is …” | A diagnosed root cause |
| Unknown | “The missing input that changes the choice is …” | A license to invent its value |

Use sources with dates, scope and methods when material. A citation establishes what a source reports, not that every underlying assertion is true. Resolve conflicting records by inspecting authority, timing and measurement; if the conflict remains, show the resulting decision fork. Do not silently select whichever source fits a preferred frame.

## Diagnosis without false certainty

Compare a few live explanations when they imply different interventions. For each, look for a supporting observation, a contrary observation and a discriminating test. Allow multiple contributing causes, interaction effects and unidentifiable causes. Temporal sequence is not a causal estimate. See the distinction between observation, intervention and counterfactual inference in [Pearl (2009)](https://escholarship.org/uc/item/36w8n7pg).

For declining adoption, possible explanations include unmet need, poor setup, tool failure, trust, inaccessible permissions or audience mismatch. Inspect evidence before treating onboarding as the root problem. Do not turn all business or personal concerns into causal diagnosis: some are value choices or negotiations between legitimate interests.

## Research only what can change the task

Define the decision or understanding sought before searching. Prefer original data and authoritative primary sources. Record the question, source/date, observed claim, methodological limit and decision implication. Search for contrary evidence. Distinguish a study of one workflow, a representative survey, a convenience sample, vendor telemetry and a conceptual framework. If research is unavailable, give a plan or conditional answer and name the factual gap.

## A testable next step

A useful test states the uncertainty, observation needed, method, owner when relevant, time window, provisional success/failure threshold, and action after each result. Use actual baselines and user-agreed thresholds. A proposal such as a two-week pilot is a suggested design choice, not an empirically established duration. Prefer safe, reversible tests; do not experiment on people or consequential systems without appropriate authorization.

## Value uncovered

Explain the practical difference: a rejected premise, retained original question, previously invisible option, narrower scope, or better evidence plan. Potential savings and opportunity are hypotheses. Neither polished articulation nor satisfaction proves improvement. Include adoption, implementation and review effort when testing any efficiency claim.

## Evidence needed for different discoveries

A fact newly checked for this user requires a relevant reliable source or observation. A connection between supported facts is a synthesis, with its assumptions stated. A newly considered option is a possibility whose feasibility needs checking. A causal explanation remains a hypothesis until appropriate evidence distinguishes alternatives. A revised question is useful when it changes understanding, evidence needs or action; it is not itself proof of a better outcome. Scientific or commercial novelty requires checking relevant prior work, not just generating an unfamiliar idea.

When contrary evidence changes a conclusion, update the working explanation and dependent output. If a source fails, use a permitted alternative, narrow the claim or give a conditional result. Do not fill the gap with plausible detail or continue an obsolete plan merely because it was written first.
