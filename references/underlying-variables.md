# Variables that can change the question

Use this map to find the next decision-changing unknown. It is a reference, not an intake form, psychological assessment, or validated measurement instrument. Inspect the context first; ask only where plausible answers would change the response or next action. Several rows may describe the same issue from different angles. Unknown does not mean mandatory to ask.

Each row defines a variable, its practical purpose, a detection cue, when to ask, when a provisional assumption is reasonable, the consequence of neglect, and the resulting change to the answer. Assumptions must be visible, reversible, and open to correction. An assumption never supplies missing authorization. “Assume” below means a working default, not a fact about the user.

Emotional context and prior experience are meaningful evidence about the person's reported situation. Acknowledge them without reducing them to noise, diagnosing a condition, or inventing a hidden motive. The user can choose a different objective from the assistant's preferred one.

## From variables to operating decisions

A variable matters when it can change a move: answer or clarify; ask the user or inspect evidence; research or proceed conditionally; compare or use an established method; revise the frame or retain it; execute or pause an affected action; correct the result or deliver and stop. The last column maps every row to such a decision. Use the [operating model](operating-model.md) for how the seven elements carry that choice through.

For example, missing information plus high undo cost can justify verification before commitment. The same missing detail in an easily revised draft can justify a visible assumption. A corrected preference changes the ranking and every dependent recommendation; it does not merely add a new note beside the old goal.

|---|---|---|---|---|---|---|
| Assumptions: propositions accepted provisionally | Exposes fragile premises | “Obviously,” or an unstated bridge | A premise could reverse the conclusion | Reversible progress is useful and labeled | Treats conjecture as fact | Verify, label, or branch — adds conditions or alternative branches |
| Evidence: observations supporting a claim | Grounds conclusions | Strong claim without examples | Support affects diagnosis or commitment | User report suffices for a bounded response | Confuses assertion with verification | Inspect records or research — changes confidence and research needs |
| Unknowns: missing relevant inputs | Focuses inquiry | A recommendation depends on a blank | Different values change next action | Plausible values lead to the same action | Misses a pivotal fork | Ask, test, or proceed — selects the next question or test |
| Uncertainty: range of plausible beliefs | Calibrates commitment | Conflicting accounts or several explanations | Resolving it earns its cost | Give robust or conditional guidance | Presents one guess as certainty | Choose robust or conditional action — changes confidence, branches, or reversibility |

|---|---|---|---|---|---|---|

| Existing solutions: approaches already available | Avoids redundant work | A request to build from scratch | Reuse or adaptation could fit | Mention relevant known options conditionally | Recreates or repeats failed solutions | Compare reuse with new work — compares reuse, change, and creation |

| Dependencies: prerequisites and external links | Exposes blocked paths | Requires another person or system | A prerequisite controls the next step | No consequential dependency is evident | Plans work that cannot proceed | Order work or use a fallback — changes order or fallback |
| Trade-offs: gains that compete with losses | Makes choice explicit | Two desirable properties conflict | Preferences determine the ranking | Present alternatives without inventing priorities | Hides costs behind “best” | Compare; ask only pivotal preferences — shows conditional recommendations |
| Opportunity cost: value displaced by this choice | Checks comparative worth | Scarce attention or resources | Another use plausibly matters more | Keep a low-cost requested task bounded | Ignores what is sacrificed | Compare effort with alternative uses — adds defer, reduce, or alternative use |

## Use the map without turning it into a script

Choose a row because it changes a live choice, not because its cell is empty. Prefer existing context to repeated questions. Name at most the few consequential gaps in the response. If many variables matter, establish a small working frame and investigate in rounds; update it when evidence or user priorities change.

For a neutral question, ask about the uncertain observation or preference before suggesting a diagnosis. For example: “What happens immediately before the delay?” keeps several explanations open. “Why does your manager block progress?” assumes both cause and motive. A useful answer can confirm the original request and proceed without reframing.
