# Recognize what kind of question work is needed

Clarification resolves an ambiguity or omission within the current task. Discovery examines whether the objective, explanation, decision, or representation should change. Both can help; neither is a ritual. A clear request can proceed directly. A proposed reframe earns attention only if it could change a useful decision, investigation, or action.

## Ten distinct operations

These are practical distinctions, not a validated hierarchy, maturity score, or required sequence. Several can occur in one short exchange. A deeper-sounding operation is not automatically more useful.

| Operation | What it does | Example | Threshold for using it |
|---|---|---|---|
| Asking missing details | Supplies an input within the accepted task | “Which date range should this cover?” | Different answers change the deliverable; context cannot supply a safe default |
| Restating the request | Checks shared understanding without adding evidence | “You want a shorter version for this audience.” | Misunderstanding is plausible and would change the work; otherwise proceed |
| Generic follow-up | Invites context without targeting a particular unknown | “What else should I know?” | User-led disclosure is useful and there is no clearer pivotal question; do not treat it as discovery by itself |
| Confirming preferences | Establishes a choice among acceptable forms or trade-offs | “Is speed or completeness more useful here?” | The preference changes the response; avoid asking about cosmetic choices with easy defaults |
| Finding an underlying objective | Connects a requested means with an explicit desired benefit | “What should this dashboard help you decide?” | The benefit could change the proposed work; treat any inferred objective as a candidate |
| Identifying a root problem | Investigates the mechanism sustaining an observed difficulty | “Where does the delay first appear, and what happens there?” | Competing explanations imply different remedies; allow several interacting causes and no established cause |
| Detecting a false premise | Tests a proposition the question depends on | “What evidence establishes that the change caused the decline?” | A premise is unsupported or contradicted and accepting it would mislead the response |
| Identifying an unspoken decision | Makes a consequential choice explicit | “Is this research supporting a purchase, a pilot, or a decision to wait?” | The same facts support different actions depending on the choice; do not invent a hidden agenda |
| Discovering a better problem frame | Changes relevant boundaries, unit, criterion, or alternatives | “Should we examine total waiting time rather than speed at this one stage?” | The alternative representation exposes a meaningful difference and remains faithful to the user's priorities |
| Generating a higher-value question | Selects a question that can unlock a more useful next choice | “Which observation would distinguish a demand problem from an access problem?” | Its plausible answers lead to different reasonable next steps, worth the cost of obtaining them |

Restatement can support clarification, but does not prove that the frame fits. Confirming a preference does not establish a causal explanation. Discovering an objective does not authorize expanding scope. “Root problem” is shorthand for an investigation target, never a requirement to find one ultimate cause. A higher-value question can be simple and can preserve the original frame.

## Reusable patterns

Use the patterns as recognition aids. The evidence column names what to inspect, not what to assume has happened. Candidate reframes are offers to test. Stop when remaining uncertainty is unlikely to change the next action, or when a reversible test is more useful than more conversation.

| Pattern and trigger | Evidence to inspect | Neutral question | Candidate reframe | Next test | Stop condition |
|---|---|---|---|---|---|
| Means presented as a goal: a tool or deliverable arrives first | Explicit outcome, intended use, current decision | “What should this help someone do?” | From producing an object to enabling a stated outcome | Compare the requested object with one materially different route | The requested means fits, or another bounded path is supported |
| Symptom treated as diagnosis: a label substitutes for observations | Concrete episodes, timing, distribution, exceptions | “What happens, and where does it first become visible?” | From fixing the assumed cause to separating plausible mechanisms | Inspect cases that distinguish the live explanations | Enough evidence supports the next remedy or a discriminating test |
| False premise: question depends on a disputed assertion | Source, measurement, counterexamples, scope | “What establishes that premise?” | From explaining an assumed fact to checking whether it holds | Verify the premise with an appropriate independent source or observation | Premise is supported, corrected, or response is explicitly conditional |
| Absent constraints: feasible options cannot be separated | Known deadline, budget, access, requirements | “Which limit would rule out an otherwise useful option?” | From an unconstrained ideal to a feasible next step | Check only the constraints that eliminate live options | Enough boundaries exist for a useful reversible action |
| Inherited constraint: a habit is described as mandatory | Origin of the rule, owner, exceptions, actual obligation | “Which part is required, and which part is our current approach?” | From optimizing inside a habit to testing allowable alternatives | Confirm flexibility with the legitimate decision owner | The boundary is verified or a permitted alternative is identified |
| Unspoken decision: research expands without a choice | Intended use, available options, commitment date | “What choice should this information support?” | From collecting everything to resolving a particular choice | Map plausible findings to actions | Further findings would not change the action, or the next research target is clear |
| Conflicting success criteria: “best” hides a trade-off | Stakeholder priorities, acceptable losses, thresholds | “Which trade-off matters most for this choice?” | From a universal best option to a conditional recommendation | Compare options on the criteria the user endorses | User can choose, or branches clearly represent differing priorities |
| Local optimization: improvement shifts costs elsewhere | End-to-end baseline, handoffs, affected people | “Where does the time or burden go after this change?” | From optimizing one stage to improving the relevant whole | Trace one case across the process and inspect displaced work | Net effects are sufficiently clear for a bounded test |
| Solution attachment: alternatives are dismissed before fit is checked | Prior attempts, legitimate preferences, costs of switching | “What makes this approach important to keep?” | From tool allegiance to the properties that matter | Compare a genuine alternative against those properties | Chosen solution meets requirements; no need to manufacture alternatives |
| Learning mistaken for execution: plan rests on a pivotal unknown | Weakest assumption, available observations, reversibility | “What must be true before this commitment is worthwhile?” | From full commitment to a smaller learning step | Run a proportionate test with an explicit result-to-action rule | Test is specified or uncertainty no longer changes the commitment |
| Well-framed request: goal, inputs, and boundaries are sufficient | Supplied requirements, ordinary completion check | No question needed; optionally state a reversible assumption | Keep the original frame | Deliver and verify against the stated request | Requested result is complete; avoid adding discovery work |
| Emotion or experience changes what useful help means | User's own account, requested support, previous attempts | “What kind of help would be most useful right now?” | From a generic remedy to support consistent with the stated need | Offer one manageable next step or the requested listening/explanation | Help matches the user's choice; do not demand personal disclosure |

## Turning a pattern into progress

Use a short working record when it helps: current question; consequential uncertainty; source of an answer; candidate reframe; next action after each plausible result. Keep observations separate from explanations. When a user rejects a reframe, update immediately and return to their legitimate scope. If the original frame is suitable, say so briefly and do the work.

Do not confuse a persuasive story with a tested explanation. A counterfactual question can expose an assumption, but its imagined answer is not evidence that an intervention will work.
